# Dune: The Battle for Arrakis (Mega Drive): разбор

Цель — перенести игру в браузер так, чтобы графика, звук и поведение остались как в оригинале.

## ROM-файлы

| Файл | Что это |
|---|---|
| `rom/dune_usa.gen` | Оригинал Westwood/Virgin 1994 (GM T-70246-00, 1 МБ) с **русским переводом группы «Шедевр» (2003)**. Контрольная сумма в заголовке не совпадает, потому что ROM правили переводчики. Графика оригинальная, переведён только текст. |
| `rom/dune_defence2.bin` | Ромхак «Dune Defence Edition 2» (EnW Projects, 2026, 1.4 МБ). Сделан на коде оригинала, графика распакована в ROM без сжатия, часть арта заменена (ментат, заставки). |

## Как устроен оригинальный ROM

* Движок тот же, что у PC-версии Dune II (Westwood): скрипты юнитов, зданий и команд лежат как IFF `FORM/EMC2` по адресам `04DB30`, `04DF62`, `04E02A` и `04E188`. Это формат `.EMC` из PC-версии, его разобрал проект OpenDUNE.
* В тексте встречаются имена файлов PC-версии (`slab.wsa`, `palace.wsa`, `hvyftry.wsa` и другие). Ресурсы адресуются по старым именам.
* **Сжатие — Westwood LCW (Format80).** Распаковщик в ROM находится по адресу `$000C32`, на Python — `tools/lcw.py`. Его вывод сверен побайтно с работой самой игры в эмуляторе: 21 вызов из 21 совпал.
* Загрузчик графики в VRAM находится по адресу `$000CD8`. Он получает список записей `[слово кол-во тайлов (бит 15 = сжато)][длинное слово адрес]`, при необходимости распаковывает данные в `$FFFF0000` и отправляет их по DMA в VRAM.
* Сжатые потоки занимают около 25% ROM, найдено 179 штук (`out/lcw_streams.json`). Тайлы обычно лежат кусками по 4096 байт (128 тайлов).
* **Картинки меню строительства** (96×56) хранятся так: палитра (16 слов CRAM) + карта тайлов 12×7 (84 слова, с флагами отражения) + слово длины + LCW-тайлы. Найдено 33 штуки, все отрендерены в `out/usa/build_pictures/`. Таблица указателей на них лежит по адресу `08F1D0`.
* Тайлы карты (песок, скалы, дюны, пряность, бетон) и тайлы зданий во время игры собираются в VRAM `001–3A5` из LCW-потоков `030890–03FDEC` и `0B2E9C–0C7xxx`. Юниты, интерфейс и шрифт частично хранятся без сжатия в диапазоне `04B000–06A000`.
* Устройство VDP во время игры: Plane A `E000`, Plane B `C000` (карта), Window `6000`, спрайты `F000`, плоскости 64×32, режим H40 (320×224). Клетка карты — 16×16 = 2×2 тайла, палитра 0 — песок, палитра 1 — бетон и здания.

### Карта и клетки (найдено для своего движка)

* **Клетка карты — 32×32 пикселя, то есть 4×4 тайла.** У PC-версии клетка 16×16.
* **Таблица иконок** — `$04ADF0`: 362 записи по 32 байта. Каждая запись — 16 слов плоскости (4 ряда по 4 тайла, с палитрой и отражениями). Нумерация иконок совпадает с PC-версией: 127 — чистый песок.
* **Тайлы ландшафта и зданий** игра при старте миссии кладёт в VRAM из 8 LCW-потоков: `0BC538, 0BCD42, 0BD774, 0BE20C, 0BED2C, 0BF8F6, 0C0500, 0C0F90` → VRAM `0000, 1000, …, 7000`.
* **Карты не генерируются по зерну, как в PC, а хранятся готовыми.** Таблица — `$01B27A`, 27 карт: по 9 на дом, в порядке экрана выбора дома (Атрейдесы, Ордосы, Харконнены). Бит 31 указателя: 1 — карта 32×32, она кладётся в позицию (16,16); 0 — карта 64×64. Байт карты — номер иконки; загрузчик (`$01B1DE`) заменяет `B0` на `7F` и `C0` на `BF`.
* **Карта в RAM** — `$FF7D9C`: 64×64 структур `Tile` по 4 байта, как в OpenDUNE (`groundTileID` — младшие 9 бит старшего слова).
* **Игровая палитра** — `$0A6C98`: 4 строки. Цвета 13–15 каждой строки — цвета домов.
* **Картинки меню строительства:** здания — таблица `$0882A4`, юниты — `$08F1D0`, по 19 штук. Порядок совпадает с перечислениями `STRUCTURE_*` и `UNIT_*` из OpenDUNE.
* **Курсоры карты** — сырые тайлы с `$064946`, по 0x100 байт: атака, движение, рамка выбора, подтверждение. Палитра — строка 3. Хранится левая половина, правая — её зеркало.
* **Движение курсора** замерено в оригинале: от 1 до 3 пикселей за кадр с разгоном примерно за 25 кадров. У края экрана курсор останавливается, и прокручивается карта.
* **Очередь DMA** — `$00038E` (`d0` — тип, `d1` — адрес назначения<<16 | длина в словах, `a0` — источник). Трассировщик — `tools/trace_dma.py`.

## Свой движок (`web/`)

Браузерная игра на TypeScript + Vite. Эмулятор не используется: при запуске игрок выбирает свой ROM, движок сам распаковывает из него графику (LCW) и рисует всё своим кодом. ROM никуда не отправляется, а хранится только в браузере игрока (IndexedDB).

```
cd web
npm install
npm run dev      # разработка, http://localhost:5173
npm run build    # сборка в web/dist
npm test         # сверка распаковщика с эталоном (нужен rom/dune_usa.gen)
```

Что уже работает:
* все 27 миссий: карта, дома, юниты, здания, подкрепления, команды ИИ и CHOAM из сценариев ROM;
* механика оригинала — движок Westwood, перенесённый из OpenDUNE (`web/src/engine/`): движение и поиск пути,
  бой, пули и ракеты, туман войны, сбор и переработка пряности, энергия и хранилища, производство, постановка
  зданий, ремонт, улучшение, подкрепления, космопорт, ИИ (скрипты UNIT/BUILD/TEAM из ROM), конец миссии;
* числа MD-версии читаются из ROM, а не берутся из PC: описания юнитов ($06C5BC) и зданий ($06AFAE) со своим
  порядком битов флагов, ландшафт ($06CCB6, у MD частично-горные клетки проходимы), тип ландшафта по иконке
  ($00581C), анимации зданий;
* управление как в оригинале: стрелки — курсор (с разгоном), 1 — A (выбрать / приказ), 2 — B (B+стрелки —
  быстрая прокрутка), 3 — C (меню приказов и строительства), Enter — Start (пауза);
* режим «Мышь» (M), как в Red Alert: левая — выбрать или приказ, протянуть — рамка, правая — отмена/снять выбор;
* набор графики: «Ресурсы» (R) → «Скачать всю графику (ZIP)»; перерисованные файлы загружаются обратно
  («Загрузить свою графику») и подменяют клетки карты, здания и юниты в любом разрешении.
* HD-графика готовых зданий на карте: 15 отображаемых типов, сохранена композиция оригинала MD;
  строительный двор — одобренный владельцем вариант с краном. У башен восемь направлений.
  Свои загруженные картинки имеют приоритет над встроенным набором.
* Full HD и HiDPI: холст использует физическое разрешение экрана, а масштаб карты, HUD и мыши
  остаётся одинаковым при системном масштабировании 100–200%.

Отладка механики без браузера: `node --experimental-transform-types` с модулями `web/src/engine/` (нужен ROM).

### Лицензия движка

Логика игры в `web/src/engine/` — перенос кода OpenDUNE (GPL-2.0), таблицы `tables.gen.ts` получены из
`src/table/*.c` OpenDUNE. Поэтому распространять игру с этим движком можно только под GPL-2.0 (с открытым
исходным кодом). Графика, звук и тексты оригинала в репозиторий не входят: движок берёт их из ROM игрока.

## Как устроен ромхак Defence Edition 2

* Перед игрой показывается экран «ЗАГРУЗКА» (~40 с), затем «глаз» со стрелками. **Нужно держать ↑ примерно 12–15 секунд.** Код экрана находится по адресу `$151F00`: счётчик удержания должен дойти до 10000 итераций, затем идёт `jmp $2008`. Удержание ↓ включает другой режим.
* Тайлсет карты лежит без сжатия по адресу `0C9AE2` (911 тайлов), картинки меню — по `063130` (палитра + 84 тайла построчно, таблица указателей по `063034`).

## Инструменты (`tools/`)

| Скрипт | Назначение |
|---|---|
| `mdrom.py` | заголовок ROM, вывод сырых тайлов, поиск палитр, карта энтропии, разбор сейвов Gens |
| `lcw.py` | распаковщик Westwood LCW |
| `scan_lcw.py` | поиск всех LCW-потоков в ROM |
| `scan_pics.py`, `render_pics.py` | поиск и рендер картинок «палитра + карта + LCW» |
| `emu.py` | безголовый эмулятор (Genesis Plus GX через libretro): кадры, VRAM, CRAM, RAM, регистры 68000 |
| `play.py` | прогон по сценарию нажатий (`w 60; p START; h UP 900; s shot`) с сохранением состояния |
| `vramdump.py` | снимок VDP из состояния: тайлы по 4 палитрам, плоскости A/B, спрайты |
| `trace_lcw.py` | трассировка вызовов распаковщика в игре (нужна сборка `gpgx_hook.so`) |
| `vram2rom.py`, `vram2lcw.py` | откуда в ROM пришёл каждый тайл VRAM |
| `m68kdis.py` | дизассемблер 68000 (capstone) |
| `extract.py` | извлечение картинок меню из ромхака |

Эмулятор собирается командой `sh tools/build_emu.sh`: она клонирует Genesis Plus GX в `third_party/` и собирает обычную библиотеку и библиотеку с хуками CPU. Нужны Python 3, Pillow, capstone (`pip install pillow capstone`), gcc и make.

ROM в репозиторий не кладётся: положите свой файл в `rom/` (папки `rom/` и `out/` в `.gitignore`).
