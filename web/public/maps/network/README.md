# Контракт сетевых карт и лобби

Каталог `catalog.json`: 12 различных карт, по три ландшафта для форматов 1v1, 2v2, 3v3, 4v4. `teamSize` определяет формат, `capacity=teamSize*2`. Карты 4v4 без суффикса сохраняют прежние id. Генерация: `node tools/generate-network-maps.mjs`.

JSON карты: строки `terrain` и `heightmap`, полный список `spawns`, `startingBuildAreas` с одинаковым количеством клеток для каждого игрока, `startingResources` с одинаковыми доступными запасами, `rules.infiniteSpice=true`, `rules.friendlyFire=false`. `impassableTerrain` и `cliffRule` должны применяться сервером и поиском пути. Проверка: `node tools/verify-network-maps-fog.mjs`.

Это подготовленные данные и визуальный интерфейс. Текущий ROM-движок ещё не загружает сетевые карты: он рассчитан на 64×64 и старые пулы участников. Не запускать эти JSON как обычный сценарий ROM без отдельного загрузчика/расширения движка.

`NetworkMenu.snapshot()` отдаёт выбранный формат, карту, параметры, пароль создаваемой комнаты и плотные id слотов 0..capacity−1. Будущий клиент получает список через `setRooms()`. Endpoint задаётся кодом, выбора сервера в UI нет. Хуки host: `refreshRooms()`, `joinRoom(id,role,password)`, `leaveObservation()`. Не логировать и не сохранять пароль открытым текстом; сервер проверяет доступ, UI не имитирует успешную проверку.

Наблюдение разрешается только для state `playing`, прекращается при `finished` или удалении комнаты. Наблюдатели не занимают слоты, не меняют состав/правила/высадки. Сетевой сервер должен подтверждать эти ограничения, запрещать огонь по союзникам и применять правило неисчерпаемого спайса (`G.infiniteSpice` в текущем движке; кампания его сбрасывает).
